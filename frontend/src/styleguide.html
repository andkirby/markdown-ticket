type icons · one glyph per CRType

Rule: one lucide glyph per type, rendered at the standard --sz-icon 16px with lucide's default 2px stroke (these are pictorial glyphs — the priority glyphs' 2.5 weight clogs them). Color is contextual, never baked into the glyph: it inherits currentColor, so inside .badge[data-type] the badge.css tint applies unchanged. Key-line glyphs carry a native title tooltip (the type name) for hover help — a title attribute, never a Radix trigger, so the glyph stays non-interactive and screen-reader-silent. Icon-only use must move the label to title + aria-label — TypeIcon renders aria-hidden.

Icon mapping (lucide, verified in lucide-react 0.542.0): Architecture → drafting-compass · Feature Enhancement → rocket · Bug Fix → bug · Technical Debt → bandage · Documentation → file-text · Research → flask-conical. Unknown type falls back to rocket, mirroring badge.css's unknown → feature tint. Delivered inline from lucide-react (tree-shaken, ~1 KB gz for all six) — not sprite/file: six glyphs don't justify a fetch that blanks the first paint of every board card.

status icons · one glyph per CRStatus

Rule: one glyph per CRStatus, ported from the owner set (public/icons/status_svg/) to 24×24 viewBox + currentColor (~2 stroke; rings 2, bold marks 2.25). Color is contextual, never baked in: the glyph inherits currentColor, so badges tint via .badge[data-status] and the key strip via .ticket-code__status-icon[data-status] — both map kebab status names to the --status-* tokens above, mirroring badge.css. Key-strip glyphs render at --sz-icon 16px with a native title tooltip (the status name — non-interactive, SR-silent); badge glyphs render at .badge__icon 12px with no title (label adjacent). StatusIcon renders aria-hidden; unmapped/missing status renders no glyph at all (graceful absence).

surface tier model — colors as signals

Each background tier signals a role — pick by what the surface does, not by look. The ladder diverges only in dark mode (base & raised are both white in light, separated by borders/shadows), so wrong-tier drift is invisible in light and glaring in dark.

base page · document reader · ticket reader · prose — "read me" (max contrast)
recessed-soft tab bars · nav rails — "chrome above content"
recessed inputs · hover fills — "inset / affordance"
raised cards · dialogs · popovers · header — "a discrete unit / floating"

Rule: reading surfaces are base. Prose on a raised tier reads lighter than the same prose on base — the bug behind "the ticket reader looks lighter than the document reader." Tab bars are recessed-soft (chrome, not content).

form controls & the surface contract

Rule: a control's fill must differ ≥3:1 from its container, or it is border-defined. A solid fill that matches its container is a ghost. Here --bg-muted is only ~1.2:1 from white — so a borderless muted input ghosts.

on elevated ← 1.2:1 ghost
on muted ← subtle on muted ← safe anywhere

disabled controls · cursor contract

Rule: a disabled control keeps pointer events and takes cursor: not-allowed — never pointer-events: none. With pointer events off, the browser skips the element under the pointer entirely: the cursor falls through to the parent and any title explaining why the control is off dies with it (hover one of the disabled buttons — the tooltip is the point). The other half of the contract: hover styles must be scoped so a dead control never reacts to pointing — Tailwind enabled:hover: in buttons.css, &:hover:not(:checked, :disabled) in pure-CSS shared objects (checkbox.css). One recipe everywhere: disabled:cursor-not-allowed disabled:opacity-50 — buttons, inputs, checkboxes, switches, dropdown items (forms.css, ui/switch, ui/dropdown-menu.tsx all follow it; buttons.css was the last pointer-events-none holdout).

toolbar toggles · filters are pressed-state buttons, labels stay

Rule (ruled 2026-09-22, MDT-206 UAT r9): a toolbar filter (Hide empty · Show badges · Show closed) is a <button aria-pressed> — never a checkbox, never icon-only. Three channels, no overlap: the label carries the verb (Hide empty vs Show closed are inverse-polarity verbs over different objects — no icon vocabulary distinguishes them, and a title tooltip is a hover-only recall tax); the icon encodes the object; the fill encodes on/off (the ramp's solid strength — compact-control recipe). No shared eye icon: eye/eye-off duplicates the verb the label already carries, and its polarity would flip meaning between controls while the fill already carries the state. Icon vocabulary reuses established glyphs: Show closed → the Implemented status glyph (it toggles exactly that status's visibility), Show badges → tag, Hide empty → square-dashed. If a slot can't earn a distinct glyph, drop the icon — label-only beats a filler eye. One-shot actions (Collapse all / Expand all) stay plain buttons — never aria-pressed; there is no state to press.

which filter is which — and which is on — lives behind a pointer event

epic badge · split chip — identity vs action

Rule: a badge that references an epic is one unit with two separately interactive zones. The identity zone — Zap glyph + key link — answers what this is: the Zap is passive and screen-reader-silent everywhere it appears (epic ContextBadge, TicketCode key line), and the key text is the only path into the epic's ticket view — every ticket key in the app opens the ticket (MDT-237 muscle memory). The action zone — a trailing, seam-separated button — answers where to go: it jumps to the Epics board focused on that epic (MDT-246, ?epic= deep link). Navigation actions take the destination's glyph: rows-3 is the Epics view (ViewModeSwitcher toggle), file-text is "open document" (the lane's open-epic button) — never the object's identity glyph. A Zap that opens a board is one mark meaning two things.

Geometry (ruled 2026-09-16, supersedes the earlier "badge grows ~4px" note): every badge on every surface renders at the same height — the canonical 20px badge box (text-xs line 16 + 2px vertical padding); the split chip never exceeds its neighbors. The action zone is a real button whose visible box is that same 20px; the MDT-236 24×24 a11y floor is still law, but it is met by an invisible hit surface — ::after, 2px above and below the button, vertical-only so it never reaches the key link — not by growing the badge. Its own hover state on the ramp's neutral tier (--state-hover-bg), title + aria-label ("Show MDT-231 on Epics board"), and stopPropagation isolation like the key link. The two controls are siblings in a group — never a button nested inside a link. The zone is legible at rest — a 1px seam derived from the badge's own color (currentColor) plus a half-strength neutral veil (color-mix 45% of --bg-muted) — and completes to the full neutral tier on hover; a bare --state-hover-bg swap measured invisible against the gold tint in dark mode, the same tint-cannot-read lesson as the scope bar. The split must be visible, not discovered by mis-clicking.

collapsed sort control

Replaces the native <select> in SortControls.tsx. One control, three sizes — degrades by breakpoint, shares one state: A icon + label + direction segment (default) · B icon-only + direction segment (tight) · C icon-only, direction inside the menu (tightest).

  • Caret removed — the segmented silhouette + popover behavior already say "opens a menu". A third glyph was buying nothing for 16px.
  • Icon-only is a degradation, not a design (B, C): at 14px calendar-1 and calendar-clock are twins, so B/C trade glanceable state for space — deliberately, only when space runs out. The label never disappears: it moves to title + aria-label, and the menu is fully labeled.
  • Direction-in-menu only in C — acceptable once the space emergency is bad enough to drop the label too. The menu shows an explicit Ascending/Descending section so the state stays visible while open. A keeps direction as a sibling segment: one click, always glanceable, and per-attribute defaultDirection can silently flip it.
  • Priority glyph note — the sort field uses chevrons-up, not the per-value PriorityIcon glyphs (Flame/ChevronUp/Equal/ChevronDown). Those mean specific priority values; reusing them for the field concept conflates two different semantics.
  • Labels drop the redundant "Date" — the calendar glyph already carries it. Updated over Update Date: past participle, matches "Created". Trigger has a fixed min-width sized to the longest label ("Priority") so the header doesn't reflow on selection.
