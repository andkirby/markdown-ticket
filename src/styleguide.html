surface tier model — colors as signals

Each background tier signals a role — pick by what the surface does, not by look. The ladder diverges only in dark mode (base & raised are both white in light, separated by borders/shadows), so wrong-tier drift is invisible in light and glaring in dark.

base page · document reader · ticket reader · prose — "read me" (max contrast)
recessed-soft tab bars · nav rails — "chrome above content"
recessed inputs · hover fills — "inset / affordance"
raised cards · dialogs · popovers · header — "a discrete unit / floating"

Rule: reading surfaces are base. Prose on a raised tier reads lighter than the same prose on base — the bug behind "the ticket reader looks lighter than the document reader." Tab bars are recessed-soft (chrome, not content).

form controls & the surface contract

Rule: a control's fill must differ ≥3:1 from its container, or it is border-defined. A solid fill that matches its container is a ghost. Here --bg-muted is only ~1.2:1 from white — so a borderless muted input ghosts.

on elevated ← 1.2:1 ghost
on muted ← subtle on muted ← safe anywhere

interaction-state ramp · hover vs active/selected

Rule: hover = the neutral tier (--state-hover-bg); active/selected = the accent family at two strengths — surface (--state-active-bg tint + --state-active-fg signal: fill + ring on in-content rows, underline on tabs, trailing check on menu rows — see menu idiom below) and solid (compact pills/badges: oklch(var(--primary)) + --primary-foreground — a tint cannot read on near-white surfaces, it measured 1.01:1 on the scope bar). Never a primary tint for hover.

collapsed sort control

Replaces the native <select> in SortControls.tsx. One control, three sizes — degrades by breakpoint, shares one state: A icon + label + direction segment (default) · B icon-only + direction segment (tight) · C icon-only, direction inside the menu (tightest).

  • Caret removed — the segmented silhouette + popover behavior already say "opens a menu". A third glyph was buying nothing for 16px.
  • Icon-only is a degradation, not a design (B, C): at 14px calendar-1 and calendar-clock are twins, so B/C trade glanceable state for space — deliberately, only when space runs out. The label never disappears: it moves to title + aria-label, and the menu is fully labeled.
  • Direction-in-menu only in C — acceptable once the space emergency is bad enough to drop the label too. The menu shows an explicit Ascending/Descending section so the state stays visible while open. A keeps direction as a sibling segment: one click, always glanceable, and per-attribute defaultDirection can silently flip it.
  • Priority glyph note — the sort field uses chevrons-up, not the per-value PriorityIcon glyphs (Flame/ChevronUp/Equal/ChevronDown). Those mean specific priority values; reusing them for the field concept conflates two different semantics.
  • Labels drop the redundant "Date" — the calendar glyph already carries it. Updated over Update Date: past participle, matches "Created". Trigger has a fixed min-width sized to the longest label ("Priority") so the header doesn't reflow on selection.

Icon mapping (lucide, verified in lucide-react 0.542.0): Key → ticket · Title → a-large-small · Priority → chevrons-up · Created → calendar-1 · Updated → calendar-clock · direction segment → arrow-up-narrow-wide / arrow-down-wide-narrow. All three share one state — click around:
